Bank Posting with Clearing

A bank receipt is posted in SAP and the matching customer invoice is cleared in the same step, through one API call. This replaces the manual SAP GUI program ZFI_BANK_PROGRAM (F-30 batch input from an Excel file).

Endpoint POST /api/bank/post SAP function Z_BANK_POST_CLEAR System A4H / client 200 Transaction logic FB05 · EINGZAHL

01What it does

For each bank receipt (one Excel row or one JSON item), the API runs this sequence:

  1. Reads and cleans the data: dates, amounts and customer numbers.
  2. Validates the data.
  3. Checks that the invoice is an open item in live SAP.
  4. Posts the receipt and clears the invoice in one SAP document.
  5. Returns the posting document and the clearing document.
  6. Writes the SAP document number back to active_bt3i / active_bs (documentid).

The accounting entry

Bank G/L 24500000
Debit10,000.00
key 40

The invoice and the payment line both get the same clearing document (AUGBL) and move from open items (BSID) to cleared items (BSAD). The posting document is the clearing document.

Why SOAP-RFC and not OData. The standard posting and clearing OData services (FAR_PAYMENT_POST_SRV, FAR_MANUAL_CLEARING_SRV) return "No System Alias" in this system, and the API user cannot create SEGW projects. An RFC-enabled function module behind SAP's built-in /sap/bc/soap/rfc endpoint needs no service registration.

03How to run

shell · from C:\SAP
# standalone server
python bank_posting\server.py --port 8001

# or the main API (port 8000)
python api.py

# CLI dry run
python -m bank_posting.posting "C:\SAP\log\BANK EXCEL SHEET.xlsx" --dry-run
Always send "dry_run": true first. A dry run validates the data and checks open items in SAP without posting anything.

SAP, inside Z_BANK_POST_CLEAR

  1. Duplicate UTR. A non-reversed document with the same document type and UTR rejects the row.
  2. Open item. The invoice must still be in BSID_VIEW.
  3. FI checks. Standard FB05 checks: period open, account valid, balance zero, field status, authorisation.
  4. Clearing confirmation. After posting, BSAD_VIEW must show the invoice cleared by the new document.

08Database write-back

document_link.py uses the same matching rules as the AR Inbox connect_document_id flow. It runs only for rows with SUCCESS or POSTED_NOT_CLEARED.

TableFilterMatchSet
active_bt3itransactiontype = 'Invoice'
documentid IS NULL		documentnumber = invoice_refdocumentid = SAP document
active_bstransactiontype = 'Bank'
documentid IS NULL		transactionref = invoice_ref or UTRdocumentid = SAP document
  • Only documentid is updated, by primary key. Existing values are never overwritten.
  • Both tables update in one database transaction.
Limitation. Invoices from the SAP sync (source_table = 'active_bsid') already hold the invoice BELNR in documentid, so they are skipped. That is why the first live posting updated 0 rows. Recommended fix: separate clearing_doc / clearing_date columns.

10Troubleshooting

MessageCause and fix
No open item in SAP …Wrong customer, company code or reference, or match_by points to the wrong field. Check FBL5N.
Amount mismatch …The bank amount must equal the open amount.
Field BSEG-VALUT does not exist …Don't send value_date for this bank G/L.
Field BSEG-HKONT does not exist …In the function module, change BSEG-HKONT to RF05A-NEWKO.
Posting period … is not openOpen the period in OB52.
UTR … already posted in document …Duplicate: the receipt is already in SAP.
