BSID to BT3I Go-Live Plan

Every minute, new and changed customer open items in SAP BSID get a passportid in active_bsid. Only those rows are sent to the Data Modelling & Ingestion service, which writes them to active_bt3i as invoices. The code is built and tested. Two steps on this machine remain before it runs on its own.

What happens to a new invoice

Example: invoice 4800000021 is posted in SAP. BSID now has 61 rows and active_bsid has 60 active ones.

  1. StepWhere the data isFor this invoice
  2. Pullevery 60 s, about 5 s
    SAP BSID → OData ZGENERIC_DATA_SRV → memory
    All 61 rows arrive as JSON. Nothing is written yet.
  3. CompareDDIC key fingerprint
    memory + active_bsid.sap_key_hash
    60 keys are known with the same values; one key is new.
  4. Store
    active_bsid masterobjectsequencingv2 sap_extraction_state
    1 INSERT: passportid PPSAP0126270000062, NEW PENDING. Counter moves to 62. Poll state records sap_count 61, new 1.
  5. Claimone run at a time
    active_bsid sap_ingestion_run
    The row becomes IN_PROGRESS with run id TR_SAP_BSID_…; the run row is RUNNING.
  6. Stage
    active_bsid_delta
    Rebuilt with just this row: passportid + 27 columns.
  7. Ingestport 8050, synchronous
    active_bt3i transaction_log dashboard + logs/jobs exports
    BT3I / Invoice / OM0000000001 row with the same passportid. transaction_log says Success. The job shows on the dashboard with its log.
  8. Close
    active_bsid sap_ingestion_run
    DONE with ingested_at; the run is SUCCESS. A failure sends the row back to PENDING, and after 3 attempts it is FAILED.

Daily operation

QuestionWhere to look / what to run
Is it running?The worker window is open; log\worker.log has a line at least every few minutes; python cli.py delta-status shows a recent last_poll_at.
Did an ingestion run?Dashboard JOBS list, entries named dm00005.active_bsid_delta, or SELECT * FROM sap_ingestion_run ORDER BY started_at DESC.
Rows stuck in PENDINGThe worker log says why. Usually the ingestion service is down or on old code; restart it.
Rows in FAILEDRead error_message in active_bsid, fix the cause, then python cli.py delta-retry BSID.
Trace one invoiceJoin active_bsid, sap_ingestion_run and active_bt3i on passportid / run id (query below).
Stop or restartCtrl+C in the worker window, then start_worker.bat. A run that was in progress is finished first.
 
-- one invoice from SAP to BT3I
SELECT b.passportid, b.belnr, b.sap_status, b.ingestion_status, r.status AS run, t.processcode, t.transactiontype
FROM active_bsid b
LEFT JOIN sap_ingestion_run r ON r.run_id = b.ingestion_run_id
LEFT JOIN active_bt3i t ON t.passportid = b.passportid
WHERE b.belnr = '4800000021';

Do not run delta-init BSID again, reload BSID through /api/extract (it is refused), or truncate active_bsid. Each of these would lose the passportids and the queue state.
