BSID Watermark Delta Plan

Load BSID in full once. After that, ask SAP every minute only for the documents entered, changed or cleared since the last pull, using the entry and change timestamps SAP already keeps. The poller no longer reads the whole table each minute.

SAP side: function Z_BSID_DELTA

A remote-enabled, read-only function module created through ADT in package $TMP, the same way as Z_BANK_POST_CLEAR. DataTwin calls it over SOAP-RFC (/sap/bc/soap/rfc) with the existing SAP user. It posts nothing.

ParameterTypeMeaning
IV_FROM_DATEDATSWatermark date (SAP time)
IV_FROM_TIMETIMSWatermark time (SAP time)
IV_BUKRSBUKRS, optionalLimit to one company code
IV_MAX_ROWSINT4Safety limit per call; more rows set EV_MORE
EV_SNAPSHOT_DATE / _TIMEDATS / TIMSSAP's clock when the query started. This becomes the next watermark.
EV_ROWS_JSONSTRINGNew and changed BSID rows, all columns, as JSON
EV_CLEARED_JSONSTRINGKeys of BSAD items cleared since the watermark
EV_MOREFLAGMore rows than IV_MAX_ROWS; call again
 
" new or changed open items
SELECT b~* FROM bsid_view AS b
  INNER JOIN bkpf AS k ON k~bukrs = b~bukrs AND k~belnr = b~belnr AND k~gjahr = b~gjahr
  WHERE ( k~cpudt > @iv_from_date OR ( k~cpudt = @iv_from_date AND k~cputm >= @iv_from_time ) )
     OR k~aedat >= @iv_from_date
     OR k~upddt >= @iv_from_date

" items cleared since the watermark (clearing document entered after it)
SELECT a~bukrs, a~kunnr, a~belnr, a~gjahr, a~buzei, a~augbl, a~augdt FROM bsad_view AS a
  INNER JOIN bkpf AS c ON c~bukrs = a~bukrs AND c~belnr = a~augbl AND c~gjahr = a~auggj
  WHERE c~cpudt > @iv_from_date OR ( c~cpudt = @iv_from_date AND c~cputm >= @iv_from_time )

AEDAT and UPDDT are dates without a time, so a document changed today is returned on every pull until midnight. DataTwin's row fingerprint sees no difference and writes nothing, so this costs a few rows per call and nothing more.

Risks and how the plan handles them

RiskSafeguard
SAP's clock and the DataTwin server differ in time zone or driftThe watermark always comes from SAP (EV_SNAPSHOT_*). The DataTwin clock is never used.
A document is stamped at 10:04:59 but committed a few seconds later, after the pullEach pull starts 5 minutes before the watermark. Rows seen twice match their fingerprint and are skipped.
A cleared invoice disappears from BSIDThe function reports BSAD items cleared since the watermark.
Some field changes do not update AEDAT / UPDDTThe nightly full compare catches them. If that is not good enough, read the SAP change log CDHDR (object BELEG, UDATE + UTIME) instead.
Watermark lost or the function failsThe poller falls back to a full read for that minute. Nothing is missed; it is just slower.
Very large backlog after downtimeIV_MAX_ROWS + EV_MORE page the result.

    SAP Basis

For BSID at 60 rows the time saved is small: about 4.5 seconds a minute. The plan matters when tables with many rows are added (BSEG, ACDOCA, BKPF), where a full read every minute is not workable.
